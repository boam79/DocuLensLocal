# 개발

설치 대상은 Windows뿐입니다. 개발·테스트는 Windows와 macOS 모두에서 합니다.

## 필요 환경

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- macOS에서 스캔 OCR까지 보려면: `brew install tesseract tesseract-lang`

```bash
git clone https://github.com/boam79/DocuLensLocal.git
cd DocuLensLocal
dotnet test
dotnet build
dotnet run --project src/DocuLensLocal.App
```

Windows PowerShell에서도 같은 `dotnet` 명령을 씁니다. SDK가 PATH에 없으면 `scripts/pack.ps1`이 `dotnet`을 찾습니다.

## 테스트

```bash
dotnet test --nologo
```

기능 검증은 이 저장소에서는 `dotnet test`가 기준입니다. (웹 제품의 배포 URL E2E와는 다릅니다.)

인덱스 경로는 테스트마다 임시 폴더를 넣어서 `%LOCALAPPDATA%`를 건드리지 않습니다. Linux에서 경로 단언은 `C:\...`가 아니라 `/docs/file.xlsx` 형태를 씁니다.

## Windows 설치 파일 만들기

```powershell
./scripts/pack.ps1
```

- `win-x64` self-contained 게시
- tessdata_fast `eng` + `kor`
- `x64/tesseract50.dll`
- Velopack `vpk -- [win] pack`
- 결과: `artifacts/Releases/DocuLensLocal-win-Setup.exe`

Linux에서 같은 일을 할 때는 `dotnet publish -r win-x64` 후 `dotnet tool run vpk -- [win] pack`을 씁니다. 이전 `*-full.nupkg`가 Releases 폴더에 있으면 델타를 만듭니다. `zstd`가 없으면 bsdiff로 떨어집니다.

Mac용 설치 스크립트(`pack.sh`, `osx-arm64`)는 두지 않습니다.

## 버전을 올릴 때

같이 맞춥니다.

- `src/DocuLensLocal.App/DocuLensLocal.App.csproj`의 `<Version>`
- `scripts/pack.ps1`의 `$version`
- `ReleaseHistory.Known` 맨 앞 항목과 테스트
- GitHub Release 태그 `v0.1.x`와 Setup.exe, `releases.win.json`, nupkg (앱 안 업데이트용)

Setup.exe를 `-Wait`로 실행하지 않습니다. 설치 UI가 에이전트 세션을 붙잡습니다.

## 코딩 때 자주 막힌 점

- Avalonia `ContentPresenter`는 `Content="{TemplateBinding Content}"`가 있어야 버튼 글자가 보입니다.
- Microsoft.Data.Sqlite는 Windows에서 `Pooling=false` + `ClearAllPools()`가 필요합니다.
- Tesseract native 파일 이름은 `tesseract41.dll`이 아니라 `tesseract50.dll`입니다.
- 빈 검색어로 전체 파일을 나열하지 않습니다.
- ZIP/HWP를 못 읽은 결과를 빈 본문 성공으로 저장하지 않습니다. 다음 패스에서 다시 읽게 둡니다.
