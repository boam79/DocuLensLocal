# 이미지 검색 제안

기준은 **0.1.29**입니다. 화면·인덱스는 아직 안 바꿨습니다. 구현은 고른 뒤입니다.

전제: 원문은 인터넷으로 안 보냄, 원본은 읽기만, 파일명이 아니라 **그림 안 내용**으로 찾기, 비기술 사용자, Mac 설치 없음.

지금 앱은 `.jpg` `.png` 같은 **사진 파일 자체를 읽지 않습니다.** PDF·Word·한글·Excel **안에 들어 있는** 스캔 그림만 OCR해서 글자를 찾습니다.

## 두 가지 “분석”

| | 그림 안 **글자** | 그림에 **무엇이 보이는지** |
|---|---|---|
| 예 | 스캔 계약서 사진에서 `부대` | 버스 사진에서 `버스` (글자는 없음) |
| 방법 | 이미 있는 Tesseract OCR | 이 PC에서 돌리는 그림 모델 |
| 클라우드 | 안 씀 | 안 씀 (3안만 씀, 비추천) |

파일명 검색은 하지 않습니다. `버스.jpg`여도 파일명만으로는 안 넣고, 그림에서 나온 단어로만 찾게 할 수 있습니다.

## 이미지 1안 — 사진 파일 OCR (가장 쉬움)

`.jpg` `.jpeg` `.png` `.tif` `.bmp`를 폴더에서 읽어, 지금 PDF 스캔과 같은 OCR로 글자를 넣습니다. 검색은 지금처럼 단어로 합니다.

- 설치본에 이미 한국어 OCR이 있습니다. 모델 추가로 안 커집니다.
- 읽는 시간은 스캔 PDF와 비슷합니다.
- **글자가 없는 사진**(풍경, 사람, 차량만)은 거의 못 찾습니다.
- 종류 칸에 **이미지**를 하나 더 둘 수 있습니다.

성공하면: 카메라로 찍은 계약서·견적 사진이 `부대`, `계약`으로 검색됩니다.

## 이미지 2안 — 이 PC에서 그림 키워드 (실제 “분석”)

인덱싱할 때 작은 그림 모델이 사진을 보고 `버스`, `간판`, `서류`, `사람` 같은 단어를 고릅니다. 그 단어를 이 파일의 검색용 글자로 저장합니다. 원본 사진은 서버로 안 보냅니다.

- 설치 파일이 **수백 MB~1GB** 더 커질 수 있습니다.
- 처음 읽을 때 사진마다 수 초가 걸릴 수 있습니다. 수백 장이면 오래 걸립니다.
- 한국어 단어는 영어보다 덜 정확할 수 있습니다. `버스 광고`처럼 세부는 놓칠 수 있습니다.
- 글자가 있는 스캔은 1안 OCR이 더 잘 맞습니다. 2안과 **같이** 쓰는 것이 보통입니다(OCR + 키워드).

성공하면: 글자 없는 현장 사진도 `버스`로 찾을 수 있습니다. 다만 사람 눈만큼 정확하지는 않습니다.

### 2안 분석은 어떻게 하나

모델이 사진을 보고 문장을 지어 내지 않습니다. **미리 준비한 한국어 단어 사전**과 사진을 비교해서, 비슷한 단어만 고릅니다.

1. 설치본에 그림 모델 파일과 한국어 단어 사전을 넣습니다. 인터넷을 쓰지 않습니다.
2. 폴더를 읽을 때 사진을 이 PC에서 숫자 묶음(특징)으로 바꿉니다.
3. 사전에 있는 각 단어(`버스`, `사람`, `서류`, `간판` …)도 같은 방식으로 미리 숫자로 바꿔 둡니다.
4. 사진 숫자와 단어 숫자가 **얼마나 비슷한지** 점수를 매깁니다.
5. 점수가 높은 단어만 남깁니다. 예: `버스 도로 간판`. `광고`처럼 사전에 없거나 점수가 낮으면 안 붙습니다.

이 방식의 이름은 CLIP(클립)입니다. 사진을 클라우드로 보내지 않고, 이 PC의 ONNX 모델로 돌립니다.

사전은 앱에 고정입니다. 사용자가 단어를 직접 적지 않습니다. 병원·현장·서류에 자주 쓰는 수백 개를 우리가 넣습니다. 사전에 없는 말은 찾지 못합니다.

다른 방법(물체 상자, YOLO)은 `사람` `차` `버스`처럼 뚜렷한 물체만 잘 찾고, `서류` `간판` `광고`는 약합니다. 그래서 2안은 **단어 비교(CLIP)** 를 기본으로 합니다.

하지 않는 것: ChatGPT·구글 비전으로 사진 보내기, 사진마다 긴 설명 문장 만들기.

### 2안 단어는 어디에 넣나

새 검색 엔진을 만들지 않습니다. 지금 문서와 같은 목록 파일(`index.db`)의 같은 칸에 넣습니다.

1. 사진 한 장 = 문서 한 줄. 경로·크기·날짜는 지금과 같습니다.
2. 고른 한국어 단어를 공백으로 이어 `body_text`에 저장합니다. 예: `버스 도로 간판`.
3. 1안 OCR을 같이 쓰면 글자 + 키워드를 한 칸에 이어 붙입니다. 예: `계약 부대 버스 서류`.
4. 검색은 지금과 같습니다. `버스 광고 찾아줘`에서 `찾아줘`를 뺀 뒤, `body_text`에 `버스`가 있는 줄을 찾습니다.
5. **파일 이름은 검색에 넣지 않습니다.** `버스.jpg`여도 모델이 `버스`를 고르지 않으면 안 나옵니다.

사진은 복사하지 않습니다. 원본 폴더의 파일을 읽기만 하고, 목록에는 단어만 남깁니다.

### 2안 정확도 · 설치 크기 · 속도

숫자는 공개 CLIP 측정과 지금 설치본(0.1.29 Setup.exe 약 **67MB**) 기준입니다. 이 PC에서 직접 잰 값은 아직 아닙니다.

**정확도**

- 사람 눈이나 ChatGPT 비전만큼은 아닙니다.
- `버스`, `사람`, `자동차`처럼 **크게 보이는 것**은 자주 맞습니다. 영어 기준 공개 시험에서 대략 100개 중 60개 안팎입니다.
- `버스 광고`, 병원 이름, 서류 종류처럼 **세부**는 약합니다. 버스를 찾아도 `광고`까지는 못 붙일 수 있습니다.
- CLIP은 영어 그림·글로 배운 모델입니다. 한국어 단어를 그대로 비교하면 거의 못 맞춥니다. 그래서 **영어 설명으로 비교하고, 저장만 한국어**로 합니다. (`a photo of a bus` → `버스`)
- 글자가 있는 스캔·계약서 사진은 2안보다 **1안 OCR**이 맞습니다.
- 점수를 느슨하게 하면 트럭을 `버스`로 넣는 실수가 납니다.

**설치 크기 (추천: 작은 CLIP)**

| | 대략 |
|---|---|
| 지금 설치 파일 | 67MB |
| 그림 모델 + 실행 도구 | **+150~250MB** |
| 2안 넣은 설치 파일 | **220~320MB** |

더 큰 모델은 정확도가 조금 오르고 설치가 **1GB 전후**까지 커지며, CPU에서는 더 느립니다. 첫 업데이트는 그 차이만큼 내려받습니다.

**속도**

- **검색은 지금과 같습니다.** 이미 넣어 둔 단어를 찾을 뿐입니다.
- 느린 것은 **사진을 처음 읽을 때**입니다.
- 일반 사무용 PC(CPU), 작은 모델: 사진 한 장 **약 0.3~2초**. 모델을 처음 불러올 때 몇 초 더.
- 사진 200장이면 **대략 1~10분**. OCR을 같이 하면 더 걸립니다.
- 그래픽 카드가 있으면 더 빠를 수 있습니다. 없어도 동작합니다.

## 이미지 3안 — 클라우드로 그림 보내기 (하지 않음)

ChatGPT·구글 비전처럼 사진을 인터넷으로 보내 분석합니다. 계약서 전제(원문 비송신)와 맞지 않습니다.

## 추천

- 찾을 것이 **스캔·사진 속 글자**면 **이미지 1안만**.
- 찾을 것이 **사진에 무엇이 찍혔는지**(버스, 건물, 사람)면 **이미지 1안 + 2안**. 2안만 하면 계약서 글자는 오히려 약해집니다.

앱 비밀번호, 클라우드 요약은 넣지 않습니다.
